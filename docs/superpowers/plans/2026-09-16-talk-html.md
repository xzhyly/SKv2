# talk.html — "Let's Talk" Conversation Shell — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development
> to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax
> for tracking.

**Goal:** Build `talk.html` — the entire "Let's Talk" conversation flow
(**four screens** — who-speaks-first, signing, speaking, thread — **plus
three modals** — confirm, idle, error) as one document that never reloads
between turns, wired to fake data only.

**Architecture:** A single self-contained HTML file, following the existing
per-feature-page convention (`sign-to-text.html`, `reports.html`,
`gesture-training.html`): one `<style>` block, one `<script>` block, no
build step, links only to already-shared assets (`css/fonts.css`,
`css/virtual-keyboard.css`, `js/virtual-keyboard.js`) plus one new shared
asset this plan creates, `css/tokens.css` (see Investigation §3). Screen
switching is a `data-screen` attribute on a top-level container, read by CSS
attribute selectors — the same primitive `index.html` already uses for
`ttsBody.dataset.state` (see Investigation §1). No screen is ever
`innerHTML`-rebuilt; only `display` is toggled via that attribute, plus
`body.modal-open` and `#modal[data-modal-kind]` for which of the three
modals (if any) is layered on top.

**Tech Stack:** Vanilla HTML5/CSS3/ES2017 JS. No framework, no build step,
no network calls. `js/virtual-keyboard.js` is reused unmodified.

## Global Constraints

*(handed to every implementer and reviewer verbatim — see the task prompt for
full text; summarized here for reference)*

- One document; screens shown/hidden, never navigated between.
- Every screen exactly 1024×600. Not responsive.
- Nothing tappable smaller than 44×44px. No body text under 16px.
- No hover states.
- One orange element per screen.
- Colours/radii/font come only from `docs/ui-target/README.md`'s palette
  (see Investigation §3). Inter is already self-hosted — no new `@font-face`.
- Bubbles: Deaf person left/white/1px border; hearing person right/navy/white
  text. Every bubble has a `Signed`/`Spoken` label + timestamp.
- Thread is persistent: appended to, never rebuilt on screen change.
- Nothing enters the thread without passing through Confirm.
- Showing a screen = attribute/class change only. No re-running setup that
  already ran.
- `onEnterSigning`/`onLeaveSigning`/`onEnterSpeaking`/`onLeaveSpeaking`/
  `onEndConversation` exist as empty functions with a one-line comment; not
  implemented.
- Fake data only. No camera, mic, MediaPipe, TensorFlow, Vosk, DB.
- Edits nothing that already exists in the repo. Creates `talk.html` and
  `css/tokens.css` only — both new files.

## Investigation (cited, per task instructions)

**§1 — index.html's screen-switching pattern, to be copied:**

- Top-level pane visibility: `dashboardPane.style.display = 'none'` /
  `translatorPane.style.display = 'flex'` — [js/script.js:344-345](../../../js/script.js#L344-L345),
  triggered from `openVoiceToSignScreen()`, itself called only after a real
  reload to `index.html?screen=voice` ([js/script.js:341](../../../js/script.js#L341),
  [js/script.js:349-350](../../../js/script.js#L349-L350)). This is the
  *coarse* pane-level version; it currently relies on reload, which talk.html
  must not do.
- Finer, same-page version — an attribute the CSS keys off, set directly by
  JS on click, no reload: `<div class="tts-body" id="ttsBody"
  data-state="initial">` ([index.html:682](../../../index.html#L682)), CSS
  `.tts-body[data-state="initial"] .tts-controls-panel{...}` /
  `.tts-body[data-state="result"] .tts-controls-panel{...}`
  ([index.html:91-107](../../../index.html#L91-L107)), set at runtime by
  `ttsBody.dataset.state = 'result'` inside `switchToResult()`
  ([index.html:794-796](../../../index.html#L794-L796)) and
  `ttsBody.dataset.state = 'initial'` inside the reset handler
  ([index.html:822-823](../../../index.html#L822-L823)).
- A second confirming precedent for the same idea (class instead of
  attribute): `#tl-page{display:none;...}` / `#tl-page.active{display:flex}`
  in [css/sign-to-text.css:27-32](../../../css/sign-to-text.css#L27-L32).
- **Decision:** talk.html uses one `data-screen` attribute on `<body>`
  (values: `who-first` / `signing` / `speaking` / `thread`), read by CSS
  attribute selectors exactly like `ttsBody`'s `data-state`. This is the one
  pattern; it is not reinvented per-screen.

**§2 — js/virtual-keyboard.js's open/close signal, to be reused, not
rewritten:**

- The script is a self-initializing IIFE that auto-attaches to *any* focused
  `<input type="text">`/`<input>` (no type)/`<textarea>` on the page via a
  global `focusin` listener — [js/virtual-keyboard.js:72](../../../js/virtual-keyboard.js#L72),
  [js/virtual-keyboard.js:79-88](../../../js/virtual-keyboard.js#L79-L88).
  talk.html only needs to include the script tag and give its text input a
  normal `type="text"`; no manual "attach" call exists or is needed.
- It signals open/closed with plain classList state, not a custom event:
  `keyboardEl.classList.add('show')` +
  `document.body.classList.add('keyboard-active')` in `showKeyboard()`
  ([js/virtual-keyboard.js:99-105](../../../js/virtual-keyboard.js#L99-L105));
  both removed in `hideKeyboard()`
  ([js/virtual-keyboard.js:107-117](../../../js/virtual-keyboard.js#L107-L117)).
  The signal to key CSS off is `body.keyboard-active`.
- The established "keyboard covers input" fix — Phase 3b / the 1024×600
  layout pass (`docs/system/UI-SURVEY-1024x600.md` finding 1, resolved in
  commit `0f077ce`) — solves the exact problem README asks talk.html to
  avoid on screen 04 ("the microphone button and its label return to their
  exact previous positions") purely with `body.keyboard-active #ttsBody
  ...` CSS selectors that reposition content, e.g.
  [index.html:478-490](../../../index.html#L478-L490),
  [index.html:516](../../../index.html#L516) — no JS-computed positions, no
  second keyboard component. talk.html's speaking screen must use the same
  CSS-only technique: `body.keyboard-active [selectors inside #screen-speaking]`.
- A `<input>` that must *not* trigger the keyboard sets
  `data-no-keyboard="true"` per [js/virtual-keyboard.js:83](../../../js/virtual-keyboard.js#L83)
  — not needed here since talk.html's only text input should always raise it.

**§3 — CSS custom properties for the palette:**

## File structure

Two files created:

- **`css/tokens.css`** — the shared palette `:root` block only (Investigation
  §3). No selectors beyond `:root`. Small and single-purpose so the three
  existing pages can adopt it later with a one-line `<link>` swap.
- **`talk.html`** (repo root, alongside `index.html`, `sign-to-text.html`,
  `reports.html`, `gesture-training.html`).

Internal sections of `talk.html`, top to bottom:
1. `<head>`: meta, title, `css/tokens.css`, `css/fonts.css`,
   `css/virtual-keyboard.css`, one inline `<style>` block (reset, header,
   status pill, collapsed strip, bubble, modal card, icon tile, then one
   block per screen — using `var(--navy)` etc. from `css/tokens.css`, no
   second `:root`).
2. `<body data-screen="who-first">`: header, status pill, collapsed thread
   strip + full thread (one persistent subtree), four screen containers
   (`#screen-who-first`, `#screen-signing`, `#screen-speaking`,
   `#screen-thread`), one modal overlay container (`#modal`) reused for the
   three modal kinds (confirm/idle/error), `js/virtual-keyboard.js`, then
   one inline `<script>` with the state machine, fake-data generators, and
   the five empty lifecycle hooks.

No JS file split out — this matches how
`sign-to-text.html`/`reports.html`/`gesture-training.html` keep their logic
inline rather than in `js/`.

## State model (interface every task relies on)

```
body[data-screen] ∈ { "who-first", "signing", "speaking", "thread" }
body.modal-open        // true while #modal is showing (confirm / idle / error)
body.keyboard-active    // set by js/virtual-keyboard.js — read-only from talk.html's CSS/JS
#modal[data-modal-kind] ∈ { "confirm", "idle", "error" }   // which content #modal shows
```

Functions every later task can call (defined in Task 1, signatures fixed for
the rest of the plan):

```js
function showScreen(name)      // name ∈ the four data-screen values above; sets body.dataset.screen = name
function openModal(kind, opts) // kind ∈ "confirm" | "idle" | "error"; opts is kind-specific (see Task 5/6)
function closeModal()          // clears body.classList.remove('modal-open')
function appendBubble({ from, text, timestamp })
                                // from ∈ "deaf" | "hearing"; appends one bubble, enforces the 30-cap (Task 4)
function onEnterSigning()  {}  // empty — later phase starts the camera
function onLeaveSigning()  {}  // empty — later phase stops the camera frame loop
function onEnterSpeaking() {}  // empty — later phase starts Vosk
function onLeaveSpeaking() {}  // empty — later phase stops Vosk
function onEndConversation() {} // empty — later phase tears down camera/Vosk before the real navigation
```

`showScreen()` is the only function that touches `data-screen`, and it is
the only place `onEnter*`/`onLeave*` are called from — each fires once, when
`data-screen` actually changes to/from that screen (not on every call), per
the "runs once, not on every transition" requirement.
